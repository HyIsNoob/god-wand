What this repo does: God Wand adds six terrain and combat spells to Minecraft, including an interactive Atomic cutscene. Fabric and NeoForge 1.21.1 share common code; Fabric and Forge 1.20.1 have separate ports. This audit assumes single-player and small dedicated servers with 2-8 players, including overlapping casts.

Audit date: 2026-10-27. This report records the audit findings and the four fixes applied after the user asked to continue. No commit, remote creation, push or publication was performed.

## Must fix

1. **Restoring a block can erase a newly placed container's contents — FIXED** ([common/src/main/java/net/godwand/spatial/SpatialDisplacementManager.java:L613](../common/src/main/java/net/godwand/spatial/SpatialDisplacementManager.java#L613))
   - **What this is:** Temporary spells save the original block and its container data, then put it back later.
   - **Problem:** A player can put a new chest in that empty space. Restoration could load the old chest data into the new chest, replacing its contents. A different newly placed block was also overwritten.
   - **Fix:** Keep the original recovery record when the source is occupied by a conflicting block or container. Restore after the obstruction is cleared; check this before removing a bridge destination. Applied to all release source roots, with regressions that failed before the fix.
   - **If we skip it:** New inventory contents or newly placed blocks can be lost. After the fix, an occupied source deliberately keeps a pending recovery record until cleared.

2. **Broken server JSON enables destructive defaults — FIXED** ([common/src/main/java/net/godwand/config/GodWandConfig.java:L114](../common/src/main/java/net/godwand/config/GodWandConfig.java#L114))
   - **What this is:** The server config decides which spells can permanently change terrain.
   - **Problem:** A syntax error in a terrain-preserving config previously returned default values with destruction enabled. The only notice was a warning in the log.
   - **Fix:** Reject startup when the server config cannot be read or parsed, and keep the original file. Client graphics config retains its existing fallback. Applied to all three release source roots; a broken-server-config regression fails on the old behavior and passes now.
   - **If we skip it:** An administrator's config typo can turn terrain damage back on.

3. **An active Spatial Path bypasses the dimension blacklist — FIXED** ([common/src/main/java/net/godwand/skill/SpatialPathWalker.java:L256](../common/src/main/java/net/godwand/skill/SpatialPathWalker.java#L256))
   - **What this is:** Spatial Path keeps running each tick after the wand is activated.
   - **Problem:** Activation checks the dimension blacklist, but the ongoing effect did not. Enabling it in the Overworld and moving to a blocked dimension could keep displacing blocks there.
   - **Fix:** Check the current dimension before ongoing bridge, shield or terrain work, then deactivate through the existing cleanup path. Applied to all release roots; regression verifies that bridge work is not called in a blocked dimension.
   - **If we skip it:** A blocked dimension still accepts an effect started elsewhere.

## Should fix

4. **The glow override affects other mods and map entities — FIXED** ([common/src/main/java/net/godwand/mixin/EntityMixin.java:L22](../common/src/main/java/net/godwand/mixin/EntityMixin.java#L22))
   - **What this is:** God Wand disables outlines on its own displaced block displays.
   - **Problem:** The condition matched every Minecraft Display, including unrelated item/text/block displays. Giving an unrelated display a glowing tag could not show its outline while God Wand was installed.
   - **Fix:** Match the existing godwand_displaced tag instead of the Display base class. Applied to all release source roots.
   - **If we skip it:** Maps and other mods lose their intended outlines.

5. **The published license was inconsistent — FIXED DURING CONSOLIDATION** ([README.md:L94](../README.md#L94), [fabric/src/main/resources/fabric.mod.json:L8](../fabric/src/main/resources/fabric.mod.json#L8), [neoforge/src/main/resources/META-INF/neoforge.mods.toml:L3](../neoforge/src/main/resources/META-INF/neoforge.mods.toml#L3))
   - **What this is:** README and Fabric metadata say MIT; NeoForge metadata says All Rights Reserved. No LICENSE file exists in this checkout.
   - **Problem:** A person downloading the source or a loader-specific jar gets conflicting reuse terms.
   - **Fix:** Confirm the intended license, add its actual LICENSE text, and make all loader metadata agree. Check third-party assets separately; this audit does not establish their rights.
   - **If we skip it:** Contributors and modpack authors cannot rely on one clear statement of permission.

6. **Joining an Atomic explosion late does not sync its visual state — OPEN** ([common/src/main/java/net/godwand/skill/AtomicManager.java:L140](../common/src/main/java/net/godwand/skill/AtomicManager.java#L140))
   - **What this is:** Atomic sends nearby clients packets when its phase changes.
   - **Problem:** A player logging in or entering range after BURST has missed the state packet. Server damage and terrain work continue, but there is no join/range synchronization to show the remaining blast on that client.
   - **Fix:** Send the existing active-cast payload once to new nearby observers. Reuse started/released timestamps so it joins at the correct time. Add a two-client regression for entering after BURST; do not restart the sequence.
   - **If we skip it:** A newly arrived player can encounter damage without seeing the current column. This was traced in code, not reproduced in multiplayer gameplay.

7. **Singularity does all initial terrain work in one server tick — OPEN** ([common/src/main/java/net/godwand/skill/ShockwaveSlicer.java:L100](../common/src/main/java/net/godwand/skill/ShockwaveSlicer.java#L100))
   - **What this is:** A full charge scans a sphere with radius 16 and displaces eligible blocks at impact.
   - **Problem:** That sphere contains 17,077 positions. The code scans them, checks adjacent exposure, and displaces all selected blocks in one call; only the visible display count is capped at 600. Several players can trigger this path close together.
   - **Fix:** Spread scanning and block changes across ticks with a shared world budget, following the existing AtomicCrater approach. Add a check for maximum work per tick.
   - **If we skip it:** Busy terrain and overlapping casts create concentrated server work. The operation count is confirmed; actual tick-time cost has not been benchmarked.

8. **The default build also made an obsolete five-skill jar — FIXED DURING CONSOLIDATION** ([build.gradle:L1](../build.gradle#L1), [src/main/java/net/godwand/item/GodWandItem.java:L44](../src/main/java/net/godwand/item/GodWandItem.java#L44))
   - **What this is:** The root project still builds the older src tree while also building the current loader modules.
   - **Problem:** The documented build succeeds but also creates a godwand-1.3.0 root artifact whose TOTAL_MODES is 5. The release modules have 6. The old Java tree adds 9,543 lines that contributors can mistakenly edit.
   - **Fix:** Make the root an aggregator for the current loader modules, then remove the superseded implementation after retaining it in Git history. Document separate Java 17 builds for the two 1.20.1 ports.
   - **If we skip it:** A maintainer can upload the wrong 1.3.0 jar or fix an inactive copy. README already warns which jars to use, so this is cleanup rather than an undisclosed runtime defect.

## Verification

- Three new data-safety regressions reproduced the old failures before production edits: build/audit-regression-before.log.

- The skill-selection server receivers validate living/non-spectator state, held slot, skill range and item ownership. Spell damage/terrain actions run on the server.
- No matches for common private-key, GitHub token, AWS access-key, OpenAI project-key or Google API-key patterns were found in current publishable text files or reachable Git patch history. This is a pattern scan, not proof that arbitrary secrets are absent.
- No Git remote is configured. Nothing has been pushed.

Verdict: The confirmed data-safety bugs are fixed. The owner selected MIT and consolidation fixed the license and obsolete-root-build findings. Treat late-observer sync and Singularity load as remaining multiplayer work before calling 1.3.0 release-ready.

Lean: -9,543 legacy Java lines, -0 dependencies possible by removing the obsolete implementation. Resource and old-test cleanup would be additional; those savings were not counted.

Not checked: Every line of legacy src and every asset/tool; native gameplay after these edits; shader/GPU behavior and FPS; production-jar dedicated-server bootstrap; multiplayer join/claims-mod compatibility; current dependency advisories; ownership/licensing of images/audio. The four dedicated development-server boots from earlier work do not prove these newer scenarios.
